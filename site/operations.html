Your workflow library

Build it once. Run it as many times as you need.

A workflow is a documented, repeatable process we build for one specific task, say, a client cancellation. Every time you need that task done, you request it, and the workflow runs again. That's one execution. Building the workflow itself is separate from running it.

In plain terms

What these words actually mean.

Workflow

A documented, repeatable sequence of steps built to complete one specific business task, like processing a cancellation.

Workflow library

The full set of workflows we've built and maintain for your business.

Workflow execution

One run of an existing workflow for one specific task or record.

You already have a cancellation workflow. Running it for Customer A is one execution. Running it again for Customer B is another.

New workflow

Designing, building, testing, and launching an additional qualifying process, separate from running an existing one.

Standard workflow

A process with a clear goal, a defined start and end, predictable inputs, and a limited number of connected systems. Something with heavy custom logic, dozens of integrations, or constant manual review gets scoped separately, never squeezed into a standard slot.
